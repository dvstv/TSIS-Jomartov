# Заметки для защиты «Открытой библиотеки»

18 слайдов; ориентир 10–12 минут. Скриншоты сделаны с работающего приложения. Код — неизменённые фрагменты файлов проекта. Проверки выполнены в облачной Linux-среде.

## 01. Открытая библиотека

Начните с назначения: это каталог книг с описаниями и обложками. Посетители просматривают книги, а зарегистрированные пользователи пополняют коллекцию. Проект выполнен по заданию TSIS I. Обозначьте стек: Python, Django, SQLite, HTML, CSS, JavaScript и Pillow. Это не онлайн-читалка: полные тексты книг не загружаются.

## 02. Что умеет приложение

Покажите главную страницу и каталог. Объясните разницу между гостем, вошедшим пользователем и администратором. Поиск работает по названию или автору; жанр ограничивает выборку. В каталоге есть пагинация по восемь книг. Администратор может редактировать и удалять записи через стандартную панель /admin/. В обычном интерфейсе редактирование и удаление пока отсутствуют.

## 03. От запроса до страницы: MTV

Разберите один запрос: браузер открывает /books/. URL-маршрут вызывает BookListView. Представление получает книги через ORM, обращающуюся к SQLite, и передаёт данные в шаблон book_list.html. Шаблон превращает данные в HTML, который получает браузер. В Django это архитектура Model–Template–View. View здесь — обработчик запроса, а не HTML-страница.

## 04. Два приложения и общая конфигурация

Объясните различие проекта и приложения. config хранит общие настройки и корневые маршруты. books отвечает за каталог, модель, формы и страницы книг. users отвечает за регистрацию и подключение стандартных обработчиков входа и выхода. templates содержит HTML, static — CSS и JavaScript. media и db.sqlite3 создаются локально и не входят в Git. manage.py запускает команды Django.

## 05. Модель Book: как хранятся книги

Откройте books/models.py. Модель описывает поля книги и становится таблицей через миграцию. У каждой записи есть автоматически создаваемый id. author — автор произведения, а added_by — пользователь, который добавил запись. ForeignKey задаёт отношение: один пользователь может добавить много книг. SET_NULL сохраняет книги после удаления пользователя. ImageField хранит имя файла; сами байты изображения находятся в media/.

## 06. Маршруты связывают URL и представления

Покажите books/urls.py. Пустой путь — главная; books/ — каталог; books/add/ — создание; books/<int:pk>/ — страница записи. int ограничивает параметр целым числом. as_view превращает класс представления в обработчик. app_name задаёт пространство имён. Имена маршрутов позволяют использовать reverse и тег url, не прописывая пути вручную во всех шаблонах. Отсутствующая книга даёт 404.

## 07. Поиск, фильтры и страницы каталога

Запрос q и genre приходит в GET-параметрах. get_queryset изменяет набор объектов: Q объединяет совпадение названия или автора через ИЛИ. Затем применяется ограничение по жанру. ListView делит результат на страницы по 8 объектов. get_context_data передаёт фильтры в шаблон и сохраняет их при пагинации. У SQLite есть ограничение поиска без учёта регистра кириллицы: в демонстрации вводите Саган с заглавной буквы.

## 08. Страница книги: один объект по ID

Покажите страницу книги и её адрес. BookDetailView наследует DetailView и получает Book по первичному ключу из URL. В шаблон объект передаётся под именем book. Там выводятся название, автор, описание, год, жанр и дата. Если есть обложка — отображается изображение, иначе заглушка. get_absolute_url возвращает канонический путь к записи; на него ведут карточки и перенаправление после добавления.

## 09. Шаблоны: наследование и повторное использование

base.html задаёт общую шапку, навигацию, подключения файлов, сообщения и подвал. Дочерние страницы используют extends и блок content. Фрагмент _card.html подключается через include на главной и в каталоге. На скриншоте видны условия if для обложки и переменные книги. Цикл for в родительской странице повторяет карточку. Пользовательские значения по умолчанию экранируются при выводе.

## 10. Загрузка обложки: проверка на сервере

Форма BookForm наследуется от ModelForm, поэтому поля и часть правил берутся из модели. Файл отправляется через POST с enctype multipart/form-data. ImageField проверяет изображение с Pillow, а clean_cover дополнительно ограничивает размер и форматы. Допускаются JPEG, PNG, WebP до 5 МБ. Медиа сохраняются в media/covers/год/месяц. Проверка обязательна на сервере, даже если есть JavaScript. FILE_UPLOAD_MAX_MEMORY_SIZE управляет памятью, а не заменяет ограничение в форме.

## 11. JavaScript: удобство до отправки формы

Скрипт main.js реагирует на изменение файлового поля. Он проверяет размер и заявленный браузером MIME-тип, затем создаёт временный URL выбранного файла и показывает изображение. revokeObjectURL освобождает старый адрес. setCustomValidity сообщает браузеру об ошибке. Это проверка для удобства пользователя; тип файла в браузере не является доказательством безопасности, поэтому сервер независимо проверяет реальное изображение.

## 12. Вход и права на добавление книги

Регистрация использует UserCreationForm и стандартную модель User. После успешной регистрации выполняется login. Для входа и выхода подключены стандартные LoginView и LogoutView. Авторизация сохраняется через сессию, а пароли хранятся как хеши. LoginRequiredMixin проверяет доступ на сервере и перенаправляет гостя на вход. При сохранении added_by назначается из request.user, а не берётся из пользовательского поля. В шапке выводится user.username.

## 13. Один сайт на широком и узком экране

Покажите широкий и мобильный скриншоты. Сетка использует CSS Grid, навигация и панели — Flexbox. Медиазапросы меняют колонки и расположение элементов. На широком экране четыре карточки в ряд, на мобильном две. Есть анимация появления карточек, эффекты наведения и видимый фокус. Для пользователей с настройкой уменьшения движения анимации отключаются. Главная проверена на ширинах 320, 390, 768 и 1440 пикселей.

## 14. Статика, медиа и защита форм

Разделите понятия: static — файлы разработчика, то есть CSS, JS и favicon; media — пользовательские обложки. В шаблонах статика подключается через load static и тег static. Адрес обложки берётся из cover.url. POST-формы содержат csrf_token. Пользовательский текст экранируется. Не заявляйте абсолютную безопасность: это базовые механизмы Django, и приложение пока работает в режиме разработки. Для публикации нужны DEBUG=0, новый секрет, HTTPS и отдельная раздача файлов.

## 15. Проверка: 16 автоматических тестов

На слайде настоящий вывод python manage.py test --verbosity 2. Тесты проверяют страницы, поиск, жанры, пагинацию и 404; регистрацию, ошибки входа и выход; создание книги и изображения; валидацию, CSRF и экранирование. Отдельно проверяется повторяемость seed_demo. Тестовая база и временные каталоги не затрагивают рабочие данные. Проверки выполнены в облачной Linux-среде, а не на физическом Mac. Дополнительно пройден сценарий в Chromium.

## 16. Запуск в VS Code на macOS

Все команды выполняются в папке с manage.py. Виртуальное окружение изолирует зависимости; requirements фиксирует их версии. migrate создаёт таблицы, seed_demo создаёт десять демонстрационных книг и обложки без повторного дублирования. Запуск выполняется через runserver. В VS Code надо выбрать .venv/bin/python через Python: Select Interpreter. Предусмотрена конфигурация отладки F5. Команды переносимы, но на физическом Mac автоматическая проверка не выполнялась.

## 17. Как показать работу на защите

Перед выступлением запустите сервер и приготовьте небольшую PNG-обложку. Покажите главную и каталог, найдите Саган и выберите жанр Наука. Откройте подробную страницу. Зарегистрируйтесь с новым именем, чтобы показать его в шапке. Добавьте новую книгу: заполните поля, покажите предпросмотр, сохраните и откройте запись. Затем выйдите и покажите, что добавление снова требует входа. В конце сузьте окно и при необходимости запустите тесты.
